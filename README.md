# Цифровой признак ТС — решение задачи 7 (Фалькон Тех), ЛЦТ 2026

Команда **DreamCore**. Прототип: **https://reid-dreamcore.onrender.com** (демо: https://reid-dreamcore.onrender.com/#demo, API: https://reid-dreamcore.onrender.com/api/docs)

Поиск того же транспортного средства на кадрах других камер без использования
госномера. На выходе — эмбеддинг ТС (2304 числа), ранжирование галереи и режим
кандидатов с отказом.

## Быстрый старт

```bash
git clone https://github.com/vexi1es/ReID && cd ReID
python get_weights.py            # веса 702 МБ из GitHub Releases (один раз), проверка SHA-256
# положить данные в ./data: test_query.csv, test_gallery.csv, images/
```

**Пакетный режим — артефакты сдачи** (одна команда, контейнер без сети):

```bash
docker compose run --rm infer    # -> ./output: submission.csv, embeddings.npy, candidates.csv, ranking_inputs.csv
```

**Сервис — веб-интерфейс и API:**

```bash
docker compose up -d             # http://localhost:8080 , Swagger: http://localhost:8080/api/docs
```

На видеокарте (нужен NVIDIA Container Toolkit): добавить `-f docker-compose.yml -f docker-compose.gpu.yml`
к любой из команд. Без GPU всё работает на CPU; провайдер выбирается автоматически.

Без Docker: `pip install -r requirements-infer.txt && python infer.py --data ./data --out ./output`;
сервис — `pip install -r requirements-service.txt && python service/dev.py`.
Версии в requirements закреплены намеренно: с более новыми onnxruntime/numpy инференс на одной
из проверочных машин падал (segfault). Инференс идёт через onnxruntime, torch не нужен.
Готовые артефакты для закрытого теста лежат в `submission/`.

**Проверка, что `submission.csv` получен моделью.** Выдача строится не только по косинусу
эмбеддингов (камера по фону, re-ranking, поправка на ракурс), поэтому рядом лежит
`ranking_inputs.csv` (предсказанные камера и ракурс каждого кадра). Скрипт пересобирает
`submission.csv` и `candidates.csv` только из `embeddings.npy` и этого файла, без картинок и моделей:

```bash
python reproduce_ranking.py --sub submission --data ./data --check   # оба файла совпадают байт в байт
```

**Тесты:** `python -m pytest -q tests` — API (поиск, отказ, ошибки ввода, режим «только чтение»,
карта внимания), re-ranking, формат и воспроизводимость артефактов сдачи.

## Архитектура сервиса

```
 браузер ──HTTP──> web (nginx: тонкий клиент + прокси /api)
                      │
                      ▼  внутренняя сеть без выхода в интернет
                   api (FastAPI) ── engine: ONNX-модели (ViT + ConvNeXt + фон камеры)
                      │
                      ▼
                   store (том): FAISS-индекс эмбеддингов + SQLite метаданных + превью ТС
```

| Этап (раздел 4 ТЗ) | Где |
|---|---|
| получение: кадр + bbox, проверка формата, размера и границ рамки | `service/api/app.py` |
| обработка: эмбеддинг ТС 2304 float32, камера по фону | `service/api/engine.py` |
| анализ: поиск по косинусу в FAISS, кадры той же камеры исключаются | `service/api/store.py` |
| результат: top-N с оценкой уверенности или отказ ниже порога | `POST /api/search` |

Основные методы API (полная спецификация — `/api/openapi.json`, Swagger UI — `/api/docs`):

| Метод | Назначение |
|---|---|
| `POST /api/search` | кадр + bbox → кандидаты с уверенностью или отказ (`refused`) |
| `POST /api/embed` | кадр + bbox → цифровой признак ТС |
| `POST /api/explain` | кадр + bbox + id кандидата → карта внимания: какие участки обеих машин дали сходство |
| `POST /api/detect` | кадр → найденные машины (рамки, класс, уверенность) для автоопределения |
| `POST /api/gallery`, `GET /api/gallery`, `DELETE /api/gallery/{id}` | ведение галереи |
| `POST /api/demo/load` | загрузить `test_gallery.csv` из `./data` в галерею |
| `GET /api/health` | состояние, размер галереи, тип индекса, CPU/GPU |

Индекс: `INDEX=flat` (точный поиск, по умолчанию) или `INDEX=hnsw` (приближённый, для галерей ~10^6).
Галерея хранится на томе `store` и переживает перезапуск; индекс пересобирается из SQLite при старте.
Сервис ищет по косинусу с исключением кадров той же камеры (один запрос — одна операция поиска);
re-ranking и поправка на ракурс используются в пакетном режиме, где вся галерея известна заранее.

**Веб-интерфейс** (`service/web`, чистый JS без внешних зависимостей, работает офлайн):
загрузка кадра (или пример из теста) → **машины на кадре находятся автоматически** (`POST /api/detect`:
Faster R-CNN MobileNetV3, torchvision, COCO, BSD-3; 96% размеченных машин теста найдены с IoU ≥ 0.5,
~130 мс на CPU) → клик по нужной рамке или своя рамка мышью → вердикт «найдено / отказ» с маршрутом
между камерами, лента кандидатов, сравнение пары в исходных пропорциях с картой внимания, экспорт
JSON/CSV, галерея. Детекция не входит в задачу (рамки даются организаторами) — это удобство оператора.
Ссылка `http://localhost:8080/#demo` сразу показывает поиск по первому примеру.
Демо-галерея прототипа — все 1860 кадров теста (`service/build_demo_store.py`: эмбеддинги и камеры
берутся из `submission/`, без повторного прогона моделей).

**Карта внимания** (`POST /api/explain`, файл `weights/reid_explain.onnx` — тот же дообученный ViT,
что и `reid.onnx`, с дополнительным выходом). Эмбеддинг = L2(BN(concat(CLS, mean(patch)))), BN на
инференсе поэлементно линеен, поэтому вклад каждого участка 14×14 px в косинусную близость двух машин
вычисляется точно (разложение сходства, Stylianou et al., WACV 2019): карта показывает, какие детали
(фонари, логотип, раскраска, крыша) дали совпадение. Без `reid_explain.onnx` сервис работает, карта
отключается. Экспорт: `python export_explain.py --ckpt runs/final/last.pt`.

## Метод

1. **Кроп ТС** по bbox с запасом 5%, 320×320 JPEG (как при обучении), затем 224×224 (ViT) и 256×256 (ConvNeXt).
2. **Эмбеддинг ТС — ансамбль двух архитектур**, каждая дообучена на train
   (ArcFace + batch-hard triplet, BNNeck, PK-сэмплер 12×4, 20 эпох):
   - DINOv2 ViT-B/14, вход 224, первые 6 блоков заморожены, вес 0.7;
   - DINOv3 ConvNeXt-Small, вход 256, заморожены stem и 2 первые стадии, lr 2e-5, bf16, вес 0.3.
   Эмбеддинг = конкатенация L2-векторов моделей с множителями √w (косинус ансамбля —
   взвешенное среднее косинусов), 1536 + 768 = 2304 числа.
   Аугментации: отражение, сдвиг, random erasing, яркость/контраст.
   **Оттенок и насыщенность не меняются** — цвет кузова является признаком идентичности.
   На инференсе — усреднение с отражённым кадром (flip-TTA), L2-нормировка.
3. **Контекст камеры.** Камеры неподвижны, поэтому камеру кадра определяем по фону:
   полный кадр 392×224, bbox ТС закрашен (сама машина и номер в признак не попадают),
   DINOv2 ViT-S/14 без дообучения, kNN (k=5) по кадрам train с известной камерой.
   Точность на отложенных ТС — 92%.
4. **Ранжирование** (`submission.csv`): k-reciprocal re-ranking (k1=10, k2=3, λ=0.3)
   по эмбеддингам ТС, затем кадры галереи с той же камеры, что и запрос, опускаются
   вниз. По протоколу оценки такие кадры либо не учитываются (та же ТС и камера),
   либо являются другой ТС, поэтому их место внизу не может ухудшить выдачу.
   **Поправка на ракурс:** определитель ракурса (DINOv2 ViT-S/14 + линейная голова, обучен
   на ручной разметке команды, точность 94.4%) помечает кадры «спереди»/«сзади»; парам
   противоположного ракурса к скору добавляется 0.08. Та же ТС с другой стороны похожа на
   запрос меньше, чем соседняя машина, снятая с той же стороны (VANet, ICCV 2019;
   VOC-ReID, AI City 2020) — поправка возвращает таких кандидатов наверх.
5. **Режим кандидатов** (`candidates.csv`): кандидат — top-1 итогового ранжирования
   (кадр с другой камеры), уверенность — косинусная близость эмбеддингов, отказ при
   близости ниже порога 0.30 (обоснование ниже).

`embeddings.npy` — L2-нормированные эмбеддинги ТС шага 2 в порядке
test_query.csv, затем test_gallery.csv. `submission.csv` детерминированно получается
из них и `ranking_inputs.csv` (камера по фону и ракурс — шаги 3–4), см. `reproduce_ranking.py`.

### Номер не используется

Модель не получает никаких признаков номерного знака: номера в данных размыты,
отдельная обработка области номера не выполняется, признак фона строится
с закрашенной машиной.

## Качество на локальной валидации

20% ТС из train отложены (модель их не видела), метрики — функциями
официального `evaluate.py`. Разбиение повторяет статистику теста: отношение
query/gallery ≈ 1.4 и ~52% запросов с кадром той же ТС той же камеры в галерее.

| Шаг | mAP@10 | Rank-1 | Rank-5 |
|---|---|---|---|
| DINOv2-B без обучения | 0.065 | 5.5% | 13.2% |
| + дообучение | 0.654 | 63.2% | 83.0% |
| + контекст камеры | 0.684 | 67.5% | 83.2% |
| + re-ranking (ViT) | 0.723 | 69.9% | 85.0% |
| ConvNeXt-S DINOv3 отдельно (+ камера + re-ranking) | 0.692 | 64.8% | — |
| Ансамбль ViT×0.7 + ConvNeXt×0.3 (+ камера + re-ranking) | 0.744 | 71.0% | 88.1% |
| **+ поправка на ракурс (итог)** | **0.766** | **73.5%** | **89.4%** |

Прирост ансамбля над одиночным ViT: +0.019…+0.021 mAP@10, парный бутстрэп по запросам
95% CI [+0.008, +0.031]. Вес 0.7 — максимум: при 0.6 и 0.8 итог 0.739 и 0.738. Без пост-обработки ансамбль даёт +0.040 (0.694 против 0.654):
архитектуры ошибаются по-разному. Шум оценки на этой валидации ≈ ±0.007, поэтому
изменения меньше 0.01 (разрешение 288, разморозка слоёв ViT) не принимались.

Финальные модели обучены тем же рецептом на всём train (+25% ТС).

Что ещё проверено и не принято (прирост итогового mAP@10 к ансамблю, парный бутстрэп):

| Вариант | Одиночная модель | Δ в ансамбле | 95% CI |
|---|---|---|---|
| ConvNeXt-Base вместо Small | 0.703 | +0.005 | [−0.003, +0.013] |
| ConvNeXt-Small на 320 px | 0.711 | +0.003 | [−0.006, +0.012] |
| 4 seed-а ViT + 4 seed-а ConvNeXt (8 моделей) | 0.706–0.723 | +0.001 | [−0.009, +0.011] |
| ViT с батчем 64 (P=16) | 0.709 | +0.001 | [−0.009, +0.011] |
| Усреднение кадров одной камеры (треклеты), 16 настроек | — | ≤ +0.003 | [−0.001, +0.006] |
| Сетка k-reciprocal (k1 4–14, k2 1–3, λ 0.2–0.6) | — | +0.004 | [−0.001, +0.008] |
| Сложение расстояний моделей вместо склейки векторов | — | +0.005 | [−0.003, +0.014] |
| Вычитание среднего вектора по камере (DMT, AI City 2021) | — | −0.004 | [−0.009, +0.001] |

Ни один вариант не превысил порог 0.01 (принята только поправка на ракурс, +0.022): выбранный ансамбль из двух моделей — потолок
этого подхода, а более тяжёлые конфигурации только замедлили бы инференс.

### Где система ошибается: ракурс

Команда разметила ракурс (спереди / сзади / сбоку) у 1 500 кадров train. Классификатор
ракурса (логистическая регрессия на признаках DINOv2-S) — точность 94.4% на отложенных кадрах.
По нему на валидации:

| Ситуация у запроса | Запросов | Rank-1 без поправки | Rank-1 с поправкой на ракурс |
|---|---|---|---|
| в галерее есть та же ТС в том же ракурсе | 551 | 81.7% | 80.9% |
| та же ТС есть только в другом ракурсе (спереди ↔ сзади) | 531 | 59.9% | **65.7%** |

Без поправки 68% ошибок top-1 — пары, где ТС нужно узнать с противоположной стороны: общими
остаются только цвет, силуэт, крыша и рейлинги. Поправка на ракурс (метод, шаг 4) даёт
+0.022 mAP@10 (парный бутстрэп, 95% CI [+0.014, +0.029]; вес 0.08 подобран на половине
запросов, на второй половине прирост +0.027) и снижает долю кросс-ракурсных ошибок до 63%.
Дальнейшее развитие: обучение с кросс-ракурсными позитивами в батче (VANet), признаки частей.

## Порог отказа

**Что считается отказом по правилам.** Засчитываются только совпадения с других камер,
поэтому запрос, у которого в галерее есть лишь кадры той же камеры, — это запрос *без пары*:
правильный ответ для него — отказ (TNR).

**Почему уверенность — по кросс-камерному кандидату.** Соседний кадр той же ТС с той же камеры
(такой «двойник» есть у ~52% запросов теста) даёт косинус ~0.9. Если брать top-1 по всем кадрам,
отказов почти не бывает: на валидации «как тест» TNR = 0 — сервис «всегда отвечает».
Поэтому кандидат — top-1 итогового ранжирования (кадры той же камеры исключены), и порог
сравнивается с его близостью. Тот же top-1 стоит первым в `submission.csv`.

| Валидация, порог 0.30 | F1 | TNR | PR-AUC |
|---|---|---|---|
| «как тест» (26 запросов без пары из 1108) — top-1 по всем кадрам | 0.970 | **0.000** | 0.971 |
| «как тест» — **top-1 с других камер (выбрано)** | 0.777 | **0.423** | **0.988** |
| 43% запросов без пары — top-1 по всем кадрам | 0.735 | 0.466 | 0.760 |
| 43% запросов без пары — **top-1 с других камер (выбрано)** | **0.708** | **0.735** | **0.850** |

Кросс-камерная уверенность лучше разделяет «есть пара / нет пары» (PR-AUC 0.988 против 0.971
и 0.850 против 0.760) и даёт осмысленные отказы.

**Выбор порога 0.30.** Зависимость от порога (итоговое решение: кросс-камерный кандидат
с поправкой на ракурс):

| Порог | «как тест» F1 / TNR | 43% без пары F1 / TNR | 43% без пары Precision / Recall |
|---|---|---|---|
| 0.25 | 0.824 / 0.308 | 0.710 / 0.548 | 0.615 / 0.838 |
| **0.30** | **0.789 / 0.500** | **0.718 / 0.769** | **0.723 / 0.713** |
| 0.35 | 0.729 / 0.654 | 0.678 / 0.860 | 0.775 / 0.602 |
| 0.40 | 0.631 / 0.846 | 0.588 / 0.922 | 0.822 / 0.457 |

0.30 — максимум F1 на валидации с большой долей запросов без пары и точка, где TNR уже выше
0.7, а полнота ещё выше 0.7. Ниже 0.30 растёт число ложных срабатываний, выше — пропусков.
На тесте при 0.30 сервис отказывает для 29% запросов. Порог меняется параметром
`--threshold` (пакетный режим) или ползунком в веб-интерфейсе.

## Скорость и ресурсы

| | |
|---|---|
| Веса | reid.onnx 347 МБ + reid_cnx.onnx 198 МБ + bg.onnx 88 МБ + view.onnx 88 МБ + банк фонов 14 МБ — **702 МБ** (лимит 2 ГБ) |
| Признак на одно ТС, батч=1 | ≈ **180 мс** = ViT 131 мс + ConvNeXt 2×24 мс (сумма замеров по моделям, flip-TTA); `--fast` — вдвое меньше |
| Пропускная способность, батч=32 | ViT 13.9 ТС/с (замер); ConvNeXt — один проход 24 мс против 66 мс у ViT |
| Признак фона кадра (камера), батч=1 / батч=32 | 39 мс / 44 кадра/с |
| Весь тест (1860 кадров) в Docker, `--cpus 16`, без сети | **311 с** (ансамбль, замер до добавления определителя ракурса); одиночный ViT — 203 с, пик 3.5 ГБ |

Замеры: Intel Core i9-14900K, onnxruntime 1.23 CPU, fp32 (`bench.py`). Машина при замере
была частично занята другими процессами — цифры справочные.

`infer.py` определяет выделенное число ядер (квота cgroup в Docker) и запускает ровно столько
потоков onnxruntime: без этого в контейнере с ограничением CPU инференс замедлялся в 5.5 раза.

Проверено: выход Docker без сети совпадает с `predict.py` (torch): косинус эмбеддингов ≥ 0.99997,
top-1 совпадает в 99.8% запросов; итоговый mAP@10 ViT на валидации через ONNX — 0.7229 (torch — 0.7228).
ConvNeXt на инференсе считается только в fp32: в bf16 эмбеддинг финальной модели искажается
(косинус с fp32 0.959), поэтому bf16 используется лишь при обучении.

Режим `--fast` (без flip-TTA) вдвое быстрее ценой mAP@10 0.7125 вместо 0.7229.
INT8-квантизация проверена и отклонена: mAP@10 падает до 0.37.

## Обучение (воспроизведение)

```bash
pip install -r requirements-train.txt
python build_crops.py --data <dataset> --out crops          # кропы ТС
python train.py --data <dataset> --out runs/v1               # с валидацией
python train.py --data <dataset> --out runs/final --full     # ViT на всём train
python train.py --data <dataset> --out runs/final_cnx --full     --backbone timm:convnext_small.dinov3_lvd1689m --size 256 --freeze 2 --lr 2e-5   # ConvNeXt
python export_onnx.py --ckpt runs/final/last.pt --out weights --name reid.onnx --weight 0.7
python export_onnx.py --ckpt runs/final_cnx/last.pt --out weights --name reid_cnx.onnx --weight 0.3 --skip-bg
python -c "from predict import build_cam_bank; build_cam_bank('<dataset>', 'weights/cam_bank.npz')"
python build_view_model.py --data <dataset> --out weights   # определитель ракурса по team_labels/ (data_labels/ в репозитории)
python postproc2_eval.py --data <dataset>                   # проверка постобработки и поправки на ракурс
```

  по результатам arXiv:2607.22068 (2026).
- Контекст камеры (взаимоисключение кадров одной камеры) — известный приём AI City
  Challenge, напр. arXiv:2104.14882.
- k-reciprocal re-ranking: Zhong et al., CVPR 2017.
- Рецепт обучения: Luo et al., *Bag of Tricks and a Strong Baseline for Deep Person
  Re-identification* (BNNeck, triplet, PK); Deng et al., *ArcFace*, CVPR 2019.
- Внешние датасеты не использовались, только данные организаторов. Разметка ракурса
  (`data_labels/`, 1 500 кадров train) сделана командой вручную.
